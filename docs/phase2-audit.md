## 1. 程式架構 (實際閱讀現有程式碼)

```
lab.html / index.html
  └ js/engine.js     Raster (CPU Float32 高度場 R=高度 G=屬性)、Walker (重取樣/速度)、
  │                  StrokeSession (把一筆 op 蓋章成高度場)、Renderer (WebGL2：模糊 2 pass → 著色 1 pass)
  └ js/brushes.js    15 支筆刷：params (形體) + shade (材質預設) + begin/point (蓋章規則)
  └ js/templates.js  路徑產生器 (script / wander)、9 組樣板規格、文字排版 (HTML 疊層 / Canvas 匯出)
  └ js/lab.js        實驗頁狀態、繪製、圖層、復原、儲存、匯出
  └ js/works.js      作品頁：延遲算繪樣板與樣本
```

### 現有資料模型 vs. 要求的概念模型 (B1)

| 概念層 | 現況 | 評估 |
|---|---|---|
| Stroke Geometry | `op.pts` = [x,y,t…]，`op.seed` | ✅ 原始座標、時間、種子不會因參數或材質改變而遺失<br>❌ 沒有壓力<br>❌ op 沒有 ID |
| Brush Shape | `layer.params` 裡屬於 `brush.params` 的鍵 | ⚠ 只能整個圖層共用，沒有單筆覆寫 |
| Material | `layer.params` 裡的材質鍵 (與形體共用一個物件，靠 schema 區分) | ⚠ 只能整個圖層共用 |
| Transform | — | ❌ 不存在 |
| Lighting | `st.light` 全域 | ✅ 全域<br>❌ 沒有局部覆寫 |
| Composition | 圖層順序、可見性、文字、背景、底圖 | ⚠ 沒有混合模式、遮罩 |
| History | 記憶體內快照 (op 物件結構共享) | ✅ 已修正為包含文件層級狀態<br>❌ 沒有可保存的版本 |
| Assets | 底圖以 dataURL 內嵌 | ⚠ localStorage 容量限制 (見 U11) |
| 格式版本 | `v: 1` | ⚠ 有版本號，但沒有遷移程式 |

**結論**：「改參數 → 用原始筆觸重新生成」這條路徑已經成立。E2、E3、E7、U3 證明它是可重現、非破壞的。缺口集中在**單筆觸層級**：沒有 ID、沒有覆寫值、沒有變換。這需要資料格式擴充，所以依指示先提出方案 (第 5 節)，還沒有實作。

## 4. 效能基準 (SwiftShader，只能當相對值)

固定資料集 (1200×800，14 筆) 高度場生成時間，取 3 次中位數：

| 筆刷 | ms | 筆刷 | ms | 筆刷 | ms |
|---|---|---|---|---|---|
| ceramic | 57 | foam | 22 | porous | 24 |
| stone | 28 | volfoam | 56 | wire | 13 |
| metal | 52 | beads | 6 | thorns | 15 |
| emboss | 17 | sand | 38 | laurel | 41 |
| paste | 53 | stipple | 55 | clay | 64 |

- **記憶體 (1400×900，每層)**：CPU 高度場 9.6MB + 堆疊快照 4.8MB (只有堆疊型筆刷會有)；GPU 紋理 9.6MB；共用模糊 FBO 38.5MB。20 層約 300MB CPU + 190MB GPU，這是目前最主要的擴充瓶頸。
- **30 層**：首次渲染 296ms，之後快取 1ms (只有變動的圖層會重新上傳)。
- **JS heap**：2.1MB → 30 層 67.9MB → 刪除後 12.5MB。高度場有被回收；剩下的是復原歷史保留的筆觸資料，屬於預期行為，不是洩漏。
- **極長筆觸**：20000 點 (約 160 秒) → JSON 394KB、重算 74ms。

依「先量測再優化」原則，目前沒有做任何效能修改。下一步最值得量測的，是記憶體隨圖層數線性成長，而不是 CPU 時間。

## 5. B2 單筆觸編輯：資料變更與相容 / 回復方案 (待確認)

### 格式 v2 (只新增欄位，不改既有欄位)
```js
op = {
  pts, seed, erase, alt, mx, my, er, es,          // v1 原有，完全保留
  id: 'S…',                                        // 新：筆觸 ID (v1 載入時以 layerId+index 決定性補上)
  ov: { size: 20, color: '#…', … },                // 新：局部覆寫值 (未出現的鍵 = 繼承圖層預設)
  xf: { tx, ty, rot, sc },                          // 新：非破壞變換，在算繪時套用到 pts，原始座標不變
  pr: [ … ]                                         // 新 (選用)：壓力，與 pts 每點對應
}
```

### 兩個必須先決定的行為
1. **單筆的「形體」覆寫** (粗細、間距…)：可以直接做。每筆用 `Object.assign({}, layer.params, op.ov)` 重新生成，同一圖層的其他筆不受影響。重新生成仍是整層重算，因為高度場有順序依賴 (堆疊、擦除)。整層重算約 15–65ms，可以接受。
2. **單筆的「材質」覆寫** (顏色、金屬度…)：同一圖層的筆觸共用一個高度場，所以會**融合**在一起，這也是石材、顏料「融成一體」的原因。給單筆不同材質只有兩條路：
   - **(A) 建議**：有材質覆寫的筆觸，在該圖層內獨立成一個子渲染項目。代價是它不再與同層其他筆觸融合，並多一張紋理。介面上會明確顯示「此筆已獨立材質，不與同層融合」。
   - (B) 高度場加材質 ID 通道，著色器查表。不會多出紋理，但重疊處只能取一種材質，並且需要大改著色器。

### 相容與回復
- v2 檔案保留所有 v1 欄位。回到 `239320e` 的舊程式仍可開啟 v2 檔案，只是會忽略覆寫與變換 (畫面會不同，但資料不會損毀)。
- 讀取 v1 檔案時自動補 `id`，第一次儲存時寫成 v2。原始 v1 檔案不會被覆寫，除非作者主動另存。
- 實作完成後，以 `tests/audit.js` 全套 + 基準圖像素雜湊比對驗收：沒有覆寫的專案，渲染必須與 v1 位元相同。

### 已知限制 (先說明)
- 擦除是圖層層級的操作。移動一筆曾被擦過的筆觸時，擦除痕跡會留在原位，不會跟著筆觸走。
- 鏡像旗標屬於筆觸；移動有鏡像的筆觸時，鏡像會同步反向移動。
